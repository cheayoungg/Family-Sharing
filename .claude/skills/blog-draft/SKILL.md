# 블로그 초안 작성

이 스킬이 호출되면 다음 순서로 진행한다:

1. `git log --since="today 00:00:00" --oneline`으로 오늘 커밋 목록을 확인한다.
2. 커밋이 하나도 없으면 사용자에게 알리고 중단한다.
3. 각 커밋에 대해 `git show <hash> --stat`과 `git show <hash>`로 변경 내용을 파악한다.
4. 변경 내용을 바탕으로 아래 구조로 블로그 초안을 작성한다:
   - 제목 (오늘 한 작업을 한 줄로 요약)
   - 오늘 무엇을 구현했는가 (기능 단위로 정리, 커밋 메시지를 근거로)
   - 왜 그렇게 설계했는가 (커밋 메시지의 "왜"에 해당하는 부분, diff에서 유추 가능한 설계 의도)
   - 막혔던 부분과 해결 과정 (있다면 — 여러 번 수정된 파일이나 revert성 커밋이 있으면 트러블슈팅으로 추정해서 질문 형태로 남겨둔다: "여기서 어떤 문제가 있었나요?")
   - 다음에 할 일 (TODO 주석이나 미완성으로 보이는 부분)
5. 코드 스니펫은 diff에서 핵심적인 부분만 3~15줄 내로 인용한다. 전체 파일을 붙여넣지 않는다.
6. 결과를 `blog/drafts/YYYY-MM-DD-<slug>.md` 경로에 저장한다. (파일명의 날짜는 오늘 날짜, slug는 주요 작업 내용을 영문 kebab-case로)
7. 저장 후 파일 경로를 사용자에게 알려주고, 본문 전체를 다시 출력하지 않는다.

톤: 회고/기록 톤. "~했다" 체가 아니라 이 프로젝트의 기존 블로그 글 톤(친근하고 솔직한 1인칭)을 유지한다. 과장하거나 없는 트러블슈팅을 지어내지 않는다 — 실제로 diff에 근거가 없으면 "막혔던 부분과 해결 과정" 섹션은 생략한다.
