# 집안일 분담(Task) API, 일정에서 만든 패턴 그대로 붙이기

가족 공유 서비스에서 은근히 제일 많이 쓰일 것 같은 기능이 "이번 주 분리수거 누가 해?" 같은 집안일 분담이에요. 오늘은 이 할 일(Task) API를 붙였어요. 일정 API를 만들면서 잡아 둔 패턴이 있어서, 이번에는 그 틀에 맞춰 채워 넣는 작업에 가까웠어요.

## 오늘 무엇을 구현했는가

커밋은 `feat: 할 일(Task) REST API 구현` 하나예요.

| Method | URL | 설명 |
| --- | --- | --- |
| GET | `/api/tasks?assigneeId=` | 담당자별 조회 (없으면 전체) |
| POST | `/api/tasks` | 등록 (`title`, `assigneeId`, `isRecurring`) |
| PATCH | `/api/tasks/{id}/complete` | 완료 체크 |
| DELETE | `/api/tasks/{id}` | 삭제 (담당자 본인만, soft delete) |

일정과 똑같이 Controller → Service → Repository로 나누고, 응답은 `{success, data, error}` 공통 포맷으로 감쌌어요. 테스트도 일정 때처럼 Testcontainers로 PostgreSQL을 띄워서 API 단위로 10개를 짰어요.

## 왜 그렇게 설계했는가

### 권한 검사는 일정과 같은 모양으로

삭제는 담당자 본인만 할 수 있어요. 일정에서 쓴 것처럼 "담당자인가?"는 엔티티가 판단하고, "아니면 403"은 서비스의 별도 메서드가 맡아요.

```java
// Task.java
public boolean isAssignedTo(Long userId) {
    return assignee != null && assignee.getId().equals(userId);
}

// TaskService.java
private void validateAssignee(Task task, Long userId) {
    if (!task.isAssignedTo(userId)) {
        throw new BusinessException(ErrorCode.FORBIDDEN);
    }
}
```

완료 체크는 누구나 할 수 있게 뒀어요. 이것도 일정의 완료 처리와 같은 기준이에요. 가족끼리는 "내가 대신 했어!" 하고 체크해 주는 경우도 있을 것 같았거든요.

### 필터 하나, 쿼리 둘

`assigneeId`가 없으면 전체, 있으면 그 사람 것만 보여줘요. 동적 쿼리를 만들 만큼 조건이 많지 않아서, 쿼리를 두 개로 나누고 서비스에서 골라 쓰게 했어요.

```java
List<Task> tasks = assigneeId == null
        ? taskRepository.findAllActive()
        : taskRepository.findAllActiveByAssigneeId(assigneeId);
```

전체 조회는 담당자가 없는 할 일도 나와야 해서 `left join fetch`를 쓰고, 담당자 필터는 담당자가 반드시 있어야 하니까 그냥 `join fetch`를 썼어요.

```java
@Query("select t from Task t join fetch t.assignee a where t.deletedAt is null and a.id = :assigneeId order by t.id")
List<Task> findAllActiveByAssigneeId(@Param("assigneeId") Long assigneeId);
```

없는 사용자 id로 필터링하면 404가 아니라 빈 배열을 돌려줘요. "이 사람이 맡은 할 일은 없다"는 결과로 보는 게 필터의 의미에 더 맞다고 생각했어요.

### `isRecurring`이라는 이름 하나에 세 가지 모습

반복 여부는 DB 컬럼이 `is_recurring`, 엔티티 필드가 `recurring`이에요. 그런데 API에서는 요청에 `isRecurring`으로 받기로 해서, 응답도 같은 이름으로 맞췄어요. 요청에는 `isRecurring`으로 보내고 응답에서는 `recurring`으로 받으면 프론트에서 헷갈릴 테니까요.

```java
public record TaskResponse(Long id, String title, Assignee assignee, boolean isRecurring, TaskStatus status) {
```

요청 DTO에서는 `Boolean`에 `@NotNull`을 붙였어요. 원시 타입 `boolean`으로 받으면 값을 빼먹어도 조용히 `false`가 되는데, 반복 여부를 실수로 빠뜨린 건지 일부러 안 보낸 건지 구분할 수가 없거든요.

## 다음에 할 일

- **반복 할 일 처리**: 지금은 `isRecurring`을 저장만 해요. 반복 할 일을 완료해도 그냥 `DONE`으로 끝나고, 다음 주기에 다시 `TODO`로 돌아오지 않아요. 매일/매주 같은 주기 정보가 필요할 것 같아요.
- **공유사항(note) API**: 이제 남은 도메인은 이것 하나예요.
- **중복 줄이기**: `validateAssignee`와 응답 안의 `Assignee { id, name }` 레코드가 일정과 할 일에 똑같이 들어가 있어요. 도메인이 하나 더 늘기 전에 공통으로 뺄지 고민해 봐야겠어요.
- **API 명세서 커밋**: 할 일 API를 명세서에 반영해 뒀는데, 아직 커밋하지 않았어요.
